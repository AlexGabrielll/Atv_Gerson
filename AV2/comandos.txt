GREENCODE API - COMANDOS SIMPLES
================================

BASE
----
A API usa SQLite em prisma/greencode.db. Nao precisa iniciar MySQL nem criar
o banco manualmente.
Servidor local: http://localhost:3000

PRIMEIRA EXECUCAO
-----------------
No terminal PowerShell do VS Code:

  npm install
  npm run configurar
  npm run dev

Deixe o terminal com npm run dev aberto. Abra outro terminal PowerShell para
usar os comandos da API.

ATALHOS NO TERMINAL DO VS CODE
------------------------------
No novo terminal, carregue os atalhos uma vez:

  . .\atalhos.ps1

Agora os comandos sao curtos:

  gc-api       Verifica se a API esta no ar.
  gc-login     Faz login e guarda o token nesta sessao.
  gc-org       Cria organizacao; pede nome e CNPJ.
  gc-contrato  Cria contrato para a ultima organizacao criada.
  gc-lote      Cria lote e equipamento para a ultima organizacao criada.
  gc-estado    Atualiza o estado do ultimo equipamento criado.

Exemplo de uso:

  gc-api
  gc-login
  gc-org
  gc-lote
  gc-estado

O usuario demo e admin@greencode.local e a senha e greencode123. Basta
pressionar Enter nos campos de login para usar esses dados.

gc-org guarda o ID da organizacao. gc-lote guarda o ID e a versao do
equipamento criado. Assim, os comandos seguintes reaproveitam esses dados
automaticamente. Eles ficam salvos somente enquanto essa sessao do terminal
estiver aberta.

Tambem e possivel passar dados sem responder as perguntas:

  gc-org 'Coleta Verde' '98765432000100'
  gc-contrato 'ID-DA-ORGANIZACAO'
  gc-lote 'ID-DA-ORGANIZACAO'
  gc-estado 'ID-DO-EQUIPAMENTO' 1

O contrato de atalho usa clausulas demonstrativas e a data atual como inicio.
O CNPJ e o codigo de barras devem ser unicos. Novos equipamentos comecam no
estado RECEBIDO, versao 1. Para mudar o estado, informe um estado permitido:
EM_TRIAGEM, EM_REPARO, RECICLADO ou DESCARTADO.

OUTROS COMANDOS
---------------
npm start          Inicia a versao compilada da API.
npm test           Executa os testes automatizados.
npm run build      Compila o TypeScript.
npm run preparar  Aplica migrations e executa o seed demo.

ESTADOS E TRANSICOES
--------------------
RECEBIDO -> EM_TRIAGEM
EM_TRIAGEM -> EM_REPARO, RECICLADO ou DESCARTADO
EM_REPARO -> RECICLADO ou DESCARTADO
RECICLADO e DESCARTADO sao estados finais.

ROTAS DISPONIVEIS
-----------------
GET   /saude                       Publica: verifica se a API esta ativa.
POST  /login                       Publica: recebe email e senha; retorna token JWT.
POST  /organizacoes                ADMIN: cria organizacao.
POST  /contratos                   ADMIN: cria contrato.
POST  /lotes                       ADMIN: cria lote e equipamentos juntos.
PATCH /equipamentos/:id/estado      JWT: altera estado e registra movimentacao.

Nao existem rotas GET para listar ou consultar organizacoes, contratos, lotes
ou equipamentos nesta versao.

RESPOSTAS DE ERRO COMUNS
------------------------
400: dados invalidos ou transicao de estado nao permitida.
401: token ausente/invalido ou credenciais de login incorretas.
403: usuario sem papel ADMIN tentou criar organizacao, contrato ou lote.
404: equipamento informado nao foi encontrado.
409: versao enviada esta desatualizada; consulte a versao atual.
